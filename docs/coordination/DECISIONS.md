## 2026-08-24 — Автоповтор загрузки фото вместо toast-and-discard
**Кто:** Claude Code
**Контекст:** обращение пользователя (21.08, Остропольцев) — фото
нарушения не сохранялось у инспектора в поле; при разборе выяснилось, что
неудачная загрузка фото при создании замечания (PR с коммитом `443d7fec`)
показывала тост и **выбрасывала** файл — инспекторы в поле тост не
замечали, замечание оставалось без доказательства.
**Решение:** каждая загрузка фото замечания автоматически повторяется до
3 раз с паузой; если и это не помогло — фото не выбрасывается, а остаётся
на экране с крупной кнопкой «Отправить ещё раз», пока не отправится или
панель не будет закрыта осознанно (с явным да/нет-вопросом, если фото ещё
не отправлены).
**Обоснование:** пользователи явно не уверены в технике (прямая просьба
владельца продукта) — решение оптимизировано под ноль требуемых действий
для типичного кратковременного обрыва связи, и под невозможность
пропустить сбой, если автоповтор не помог.
**Связано:** PR #108.

## 2026-08-21 — `checklist_items.category` не может быть сразу deprecated
**Кто:** Codex CLI (поправил ошибочное предположение в черновике Claude Code)
**Контекст:** при написании `docs/STATS_MODEL_V2.md` Claude Code утверждал,
что старая текстовая колонка `checklist_items.category` "deprecated, код её
больше не читает" — не проверив по всей кодовой базе.
**Решение:** колонка остаётся в переходный период с dual-write (новый
`category_id` пишется вместе со старым текстовым полем) — она активно
читается в `pdf_report.py` и пишется в `checklists.py` для PDF-отчётов.
Полное удаление — отдельная миграция после аудита продакшен-интеграций,
не часть Statistics v2.
**Обоснование:** утверждение «код не читает X» нельзя делать по одной
модели — только по grep'у всех вызовов в кодовой базе. Прямая иллюстрация
правила ревью в `AGENTS.md`.
**Связано:** `docs/STATS_MODEL_V2.md` §3.2, PR #104 (закрыт), коммит `f7de857`.

## 2026-08-21 — `bulk-accept` только для reviewer, admin — 403
**Кто:** Codex CLI и Claude Code — независимо пришли к одному решению
**Контекст:** `POST /inspections/bulk-accept` изначально был доступен и
reviewer, и admin; по своей конструкции (кандидаты — только "зелёные"
обходы: `completed && !reviewed_by && issues_count==0`) вариант "admin
обрабатывает только незелёные" для этого эндпоинта структурно невозможен.
**Решение:** массовая приёмка — только для reviewer; admin получает 403
с сообщением «Массовая приёмка — только для проверяющего». Одиночная
приёмка (`PATCH /inspections/{id}`) для зелёного обхода админом — тоже 403;
для незелёных права admin не меняются.
**Обоснование:** роль admin в цепочке — финальное решение по незакрытым
замечаниям, а не штамповка чистых обходов; это разделение труда.
**Связано:** `docs/STATS_MODEL_V2.md` §4.1, коммит `f7de857`.

## 2026-08-20 — Причина конфликта миграций PR #104 / основание для AGENTS.md
**Кто:** Claude Code (пост-фактум разбор)
**Контекст:** Codex CLI и Claude Code независимо и параллельно
реализовывали `docs/STATS_MODEL_V2.md` — оба создали Alembic-ревизию
`add_issue_categories` от одного и того же `down_revision = "a8b9c0d1e2f3"`,
с разными revision ID (`b9c0d1e2f3a4` у Codex, `b1c2d3e4f5a6` у Claude
Code). Codex смержил свою первой (коммит `f7de857`); PR #104 (Claude Code)
пришлось закрыть без мержа — `alembic upgrade head` иначе упал бы с
multiple heads, независимо от качества содержимого самого PR.
**Решение:** закрыть PR #104 без мержа, не воскрешать. Установить
координационный протокол (`AGENTS.md`, этот каталог) на будущее.
**Обоснование:** дешевле свериться с историей перед стартом, чем
переделывать часы параллельной работы.
**Связано:** PR #104 (закрыт), PR #107 (`f7de857`), `AGENTS.md`.
