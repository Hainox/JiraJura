## 2026-09-03 — Генеральная уборка: удалён мёртвый код, обновлена документация
**Кто:** Claude Code
**Контекст:** владелец продукта попросил «генеральную уборку» — привести
репозиторий и документацию в порядок. За 10 дней без ревизии документация
(README, доска задач) разошлась с кодом, а в репозитории накопились файлы,
не имеющие отношения к текущей разработке.
**Решение:**
- Удалён корневой `scripts/` (5 файлов): разовые локальные скрипты от
  05.08.2026 с захардкоженными путями `C:\Users\dmitr\Downloads\...` —
  использовались один раз при самом первом заведении пользователей в БД,
  ни разу не менялись и нигде не упоминались за все 146 PR с тех пор.
- Удалён `.superdesign/init/` (6 файлов): авто-сгенерированный снимок
  кодовой базы (роуты/страницы/компоненты) от инструмента дизайна на
  24.08.2026 — не поддерживался, устарел, нигде не referenced.
  `.superdesign/design-system.md` (актуальный, вручную написанный документ
  про визуальный язык — шрифты, цвета статусов, копирайтинг статистики) —
  сохранён, перенесён в `docs/design-system.md`.
- `README.md` и `backend/README.md`: списки роутеров/сервисов/страниц
  фронтенда обновлены до фактического состояния кода (не хватало
  `courtyards`, `feedback`, `stats`, `checklists` и 5 страниц админки).
  Исправлено ложное утверждение «чек-листы сохранены только для
  просмотра истории» — по факту дефект по пункту чек-листа активно
  создаёт новое нарушение с критичностью/сроком по типу пункта
  (`backend/app/routers/inspections.py`).
- `docs/coordination/STATUS.md` приведена в соответствие с `main`
  (несколько строк 10-дневной давности были помечены `in_progress`/
  `planned`, хотя по `git log` уже смержены и в проде).
**Обоснование:** README и доска задач читают в первую очередь новые
агенты/люди в начале сессии — расхождение с реальным кодом стоит им
времени на самостоятельную перепроверку каждого факта. `scripts/` и
`.superdesign/init/` не несли риска (не импортировались никаким кодом),
поэтому решение об удалении принято безопасно, без запроса подтверждения.
**НЕ тронуто (осознанно):** `docs/ARCHITECTURE_RESEARCH.md` и
`docs/STATS_MODEL_V2.md` — на них ссылается README как на источник
роадмапа/модели, это живые справочные документы, а не мусор. 32
GitHub-ветки, не смерженные по git-ancestry (в основном соответствуют уже
squash-смерженным PR — этот проект мержит через squash, поэтому
`--no-merged` их не ловит корректно) — удаление веток видимо для всех
участников и является более необратимым действием, чем правки файлов в
PR; предложено владельцу продукта отдельно, не выполнено агентом
самостоятельно.
**Связано:** отдельный PR (см. `git log` для точного номера), файлы —
`README.md`, `backend/README.md`, `docs/design-system.md`,
`docs/coordination/STATUS.md`.

## 2026-08-24 — Автоповтор загрузки фото вместо toast-and-discard
**Кто:** Claude Code
**Контекст:** обращение пользователя (21.08, Остропольцев) — фото
нарушения не сохранялось у инспектора в поле; при разборе выяснилось, что
неудачная загрузка фото при создании замечания (PR с коммитом `443d7fec`)
показывала тост и **выбрасывала** файл — инспекторы в поле тост не
замечали, замечание оставалось без доказательства.
**Решение:** каждая загрузка фото замечания автоматически повторяется до
3 раз с паузой; если и это не помогло — фото не выбрасывается, а остаётся
на экране с крупной кнопкой «Отправить ещё раз», пока не отправится или
панель не будет закрыта осознанно (с явным да/нет-вопросом, если фото ещё
не отправлены).
**Обоснование:** пользователи явно не уверены в технике (прямая просьба
владельца продукта) — решение оптимизировано под ноль требуемых действий
для типичного кратковременного обрыва связи, и под невозможность
пропустить сбой, если автоповтор не помог.
**Связано:** PR #108.

## 2026-08-21 — `checklist_items.category` не может быть сразу deprecated
**Кто:** Codex CLI (поправил ошибочное предположение в черновике Claude Code)
**Контекст:** при написании `docs/STATS_MODEL_V2.md` Claude Code утверждал,
что старая текстовая колонка `checklist_items.category` "deprecated, код её
больше не читает" — не проверив по всей кодовой базе.
**Решение:** колонка остаётся в переходный период с dual-write (новый
`category_id` пишется вместе со старым текстовым полем) — она активно
читается в `pdf_report.py` и пишется в `checklists.py` для PDF-отчётов.
Полное удаление — отдельная миграция после аудита продакшен-интеграций,
не часть Statistics v2.
**Обоснование:** утверждение «код не читает X» нельзя делать по одной
модели — только по grep'у всех вызовов в кодовой базе. Прямая иллюстрация
правила ревью в `AGENTS.md`.
**Связано:** `docs/STATS_MODEL_V2.md` §3.2, PR #104 (закрыт), коммит `f7de857`.

## 2026-08-21 — `bulk-accept` только для reviewer, admin — 403
**Кто:** Codex CLI и Claude Code — независимо пришли к одному решению
**Контекст:** `POST /inspections/bulk-accept` изначально был доступен и
reviewer, и admin; по своей конструкции (кандидаты — только "зелёные"
обходы: `completed && !reviewed_by && issues_count==0`) вариант "admin
обрабатывает только незелёные" для этого эндпоинта структурно невозможен.
**Решение:** массовая приёмка — только для reviewer; admin получает 403
с сообщением «Массовая приёмка — только для проверяющего». Одиночная
приёмка (`PATCH /inspections/{id}`) для зелёного обхода админом — тоже 403;
для незелёных права admin не меняются.
**Обоснование:** роль admin в цепочке — финальное решение по незакрытым
замечаниям, а не штамповка чистых обходов; это разделение труда.
**Связано:** `docs/STATS_MODEL_V2.md` §4.1, коммит `f7de857`.
