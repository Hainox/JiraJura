# Подключение пользователей к «Журналу обхода площадок»

Регистрация в системе — только по приглашению от администратора. Открытой
самостоятельной регистрации нет: это внутренний инструмент с данными по
объектам округа.

Адрес системы: **https://journal.yuvibot2.xyz:8443**

## Роли

| Роль | Кому выдавать | Что видит | Что может |
|---|---|---|---|
| **Инспектор** | Сотрудник, который ходит по площадкам | Площадки своего района, свои обходы и замечания | Проводить обходы: заполнять чек-лист, фотографировать, фиксировать замечания |
| **Проверяющий** | Руководитель/куратор, контролирующий работу | Все обходы и замечания своей зоны: если при приглашении указан район — только этот район; если район не указан — весь округ | Всё, что инспектор, плюс: просматривать чужие обходы, менять статусы замечаний (назначено → в работе → устранено → закрыто), скачивать Excel-выгрузку |
| **Админ** | Ответственный за систему (1–2 человека) | Всё без ограничений | Всё вышеперечисленное, плюс: приглашать пользователей, менять их роли и районы, отключать учётные записи |

## Как пригласить пользователя (делает админ)

1. Войдите в систему под админом.
2. В правом верхнем углу нажмите иконку **людей** → откроется страница «Пользователи».
3. Нажмите **«Пригласить пользователя»**.
4. Заполните форму:
   - **Логин** — латиницей, без пробелов (например, `ivanov_ai`). Под ним человек будет входить.
   - **ФИО** — полностью, отображается в журнале и отчётах.
   - **Роль** — см. таблицу выше.
   - **Район** — для инспектора обязательно укажите его район; для проверяющего: выбран район — контролирует только его, не выбран — весь округ. У админа поля района нет.
5. Нажмите **«Создать приглашение»** — появится зелёный блок со ссылкой вида
   `https://journal.yuvibot2.xyz:8443/register/<код>`.
6. Скопируйте ссылку (кнопка с иконкой копирования) и передайте сотруднику
   любым удобным способом (мессенджер, почта, лично).

⚠️ Важно про ссылку:
- Действует **72 часа** и срабатывает **один раз**. Не успел — просто создайте новое приглашение.
- Ссылка показывается **только один раз** сразу после создания. Закрыли страницу — создайте новую.
- Пароль сотрудника админу неизвестен и нигде не передаётся — его задаёт сам сотрудник. Это сделано специально.

## Что делает приглашённый сотрудник

1. Открывает полученную ссылку (можно с телефона).
2. Видит страницу «Регистрация» со своим ФИО и ролью — проверяет, что это он.
3. Придумывает и дважды вводит пароль.
4. После подтверждения сразу попадает в систему уже залогиненным.

Дальше вход обычный: адрес системы → логин → пароль.

## Управление пользователями (админ)

На странице «Пользователи» таблица всех сотрудников: ФИО, логин, роль, район, статус.

- **Отключить сотрудника** (уволился, ушёл в отпуск): клик по статусу
  «активен» → станет «отключён». Войти он больше не сможет, все его прошлые
  обходы и замечания сохраняются. Обратный клик включает доступ снова.
  Удаления пользователей нет намеренно — история должна сохраняться.
- **Сменить роль или район**: сейчас через API/администратора системы
  (в интерфейсе пока не выведено).

## Если сотрудник забыл пароль

Самостоятельного восстановления пароля пока нет. Сброс делает администратор
сервера одной командой (на сервере, в `/opt/jirajura`):

```bash
docker compose -f docker-compose.prod.yml exec db psql -U postgres -d sao_inspection -c "
UPDATE users SET password_hash = crypt('НОВЫЙ_ПАРОЛЬ', gen_salt('bf')) WHERE login = 'ЛОГИН';
"
```

Сообщите сотруднику новый пароль по защищённому каналу и попросите
никому его не передавать.

## Рекомендуемый порядок подключения подразделения

1. Админ создаёт приглашения для **проверяющих** (по одному на район, либо
   одного на округ без указания района).
2. Затем — приглашения для **инспекторов**, каждому строго его район.
3. Каждому отправляется его личная ссылка. Проверьте на следующий день на
   странице «Пользователи», все ли зарегистрировались — у неактивированных
   приглашений истекает срок, тогда создайте повторное.
